pi-scout · add-on for the pi AI agent · Nov 2026

A sidekick that finds what an AI agent doesn't know it's missing

pi-scout runs next to an AI agent while it works. It searches your files and tools on its own, then hands the agent a short list of places worth checking. The agent decides what to open.

The problem

In a big folder, one note changes the answer

Ask an AI agent to write a client email from a folder of 3,000 notes. It reads what looks relevant and gets to work. The note that matters — a newer price, a decision from a meeting, a correction in a chat — often uses different words, so the agent never opens it and writes the old answer.

When someone points the agent to that note, it nearly always uses it. Finding it is the hard part.

How it works

Two workers, side by side

The agent does the task. The scout is a separate, cheaper AI that only searches. It starts when you give the task, works in parallel, and about 8 seconds later slips one short list into the agent's conversation.

The list points to places, never to answers: a file or message, its date, and whether something newer exists on the same subject. It stays short: a few hundred words at most.

Scout: places worth checking 1. emails/harbour/2026-03-02 re: launch timing.txt Mar 2 · newer than 2 2. plans/launch-plan-v3.md Jan 10 · older 3. ticket #4117 "Pricing exception" (helpdesk) Feb 28 4. notes/2026-02-14 steering committee.md Feb 14

The dates and "newer than" links let the agent tell a current note from an outdated one, instead of trusting whichever it opens first.

How the scout searches

Each time you give a task, the scout makes three calls to a small, fast AI model (Claude Haiku in the tests):

  • Plan: from the task and an overview of the folder, it writes many searches: synonyms, the other language (English/French), names of people and clients, and how a rule or a correction would be worded.
  • Gather: it runs them on files, history and connected tools, adds the newest files of the folders it picked, and summarises about 100 candidates in a line or two each.
  • Judge and follow up: it keeps the most promising ones, runs a second round of searches based on what it found, and keeps up to 12. Copies of the same file are merged, newest first.

The list skips anything the agent has already opened. One list per task.

Where it looks

Your files, and the tools you connect

Files

The files in the folder the agent works in: notes, docs, emails saved as text, data files.

History

Commit messages, when the folder is a git repository: decisions often live there.

Connected tools

Search tools you list in a config file: tickets, CRM, team chat, web search.

Privacy and safety rules
  • Files only by default. A tool is searched only if you list it in ~/.pi/agent/scout-sources.json, and only its read-only search and fetch functions are used.
  • Same AI provider as your session. Short summaries of candidates go to the scout's model on the provider you already use. Passwords, keys and tokens are blanked out first.
  • Web searches get only your own words. Names and details from your files are never sent to public search.
  • Public pages stay in their place. At most 3 web results per list, and a web page can never mark one of your own documents as outdated.
  • Limits on every run: capped number of tool calls, a few seconds per call, and a token budget per session.

How well it works

It helps most in big folders

We tested it on generated folders — notes vaults, wikis, shared drives, code repos, ticket and chat systems — each hiding one note the task depends on. Each bar is how often the agent's final answer used that note.

Current version25 practice folders
54 → 66 %
  • Big folders gain the most. In small folders the agent already reads nearly everything on its own.
  • The final blind test shows a small gain that could still be chance; its big folders went from 36 % to 58 %.
  • It stayed safe: answers were never worse overall, a booby-trapped web page was never followed, and the scout never changed anything.
  • It costs little: about 10–25 thousand tokens of a small model per task, and the main agent used about 40 % fewer tokens because it explored less.
How it was tested
  • Each test folder hides one key note, written with different words from the task, among decoys such as an outdated "official" version and near-duplicates. A script checks the final answer.
  • Every setup runs side by side on the same folders: the agent alone, the agent with the scout, and the agent given the key note directly (the best possible case).
  • The scout was frozen before each test, and the pass rule was written down in advance. Each blind set was used once.
  • The agent in all tests was Claude Haiku 5.5, running in a sandbox that could only see its own folder.
What the numbers above measure exactly
  • Big folders (33 → 88 %): 24 runs per setup, +54 points, p < 0.001. The agent given the note directly reached 92 %. Measured with the previous version, where the agent asked for the list itself.
  • Final blind test (45 → 53 %): 96 runs per setup, +8 points, p = 0.29. Big folders only: +22 points, p = 0.10. Same previous version.
  • Current version (54 → 66 %): 50 runs per setup. It came within 4 points of the previous version, while delivering the list automatically. Main-agent tokens: 195k against 337k for the agent alone.

Keep in mind

Limits

  • Tested on generated folders with one agent model; real notes are messier.
  • The list can include an outdated document. The dates and "newer than" links usually steer the agent to the current one, but not every time.
  • It adds a few seconds before the list arrives, and pays off mainly in folders too big to read entirely.
How it got here

Seven versions over three days. Early ones slipped a single confident tip into the agent; it trusted the tip even when it was wrong, so results suffered. The current design gives a dated list of several places and leaves the choice to the agent. The search moved from small local models, which couldn't judge relevance, to a small cloud model that plans and judges its own searches.

Install

pi install git:github.com/cfstcyr/pi-scout for every session, or add -l inside one folder to install it there only. Optional: list connected tools in ~/.pi/agent/scout-sources.json (example in the repository).
